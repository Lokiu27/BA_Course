# Модуль 5. Spec-driven development: полный цикл с AI

**Время модуля: 3.5-4 часа.** Статус: план модуля, уроки разрабатываются по нему.

## Зачем этот модуль

AI вы использовали уже с первого модуля - теперь собираете картину целиком. Это кульминация курса: мы дошли до шагов "реализация" и "проверка" цикла (намерение → спецификация → реализация → проверка → опыт), и все, что вы построили в модулях 1-4 - намерение, глоссарий, модели, требования - заработает как единая система.

За модулем стоит сдвиг, который уже меняет команды: код ничего не стоит - вся работа переносится на уровень спецификации. Пока реализацию генерирует агент, в цепочке создания системы остается два человека: **бизнес-аналитик**, который превращает проблему бизнеса в бизнес-требования, и **архитектор решения** (он же разработчик), который превращает их в спецификацию системы. Все остальное делает агент. Если эти двое отработали хорошо, хорошим будет и результат; если спецификация неполна - агент уверенно достроит ее додумками. Узнаете урок 1.3? Ничего не изменилось: мусор на входе - мусор на выходе. Просто теперь мусор генерируется быстрее.

Ключевая формула - она сопровождает вас с первого урока:

```
Knowledge in heads → structured artifacts → AI assistance
(знания в головах)   (структурированные        (помощь AI)
                     артефакты)
```

Аналитик задает структуру и правила. AI помогает поддерживать систему. Ответственность - на аналитике.

## Результаты модуля

После модуля вы сможете:

1. Системно применять AI-инструменты в аналитике: генерация требований и документации, проверка консистентности, преобразование артефактов (BPMN → черновик документа), генерация по стандартам (ГОСТ, ISO).
2. Строить рабочий цикл "человек + AI": поставить задачу по структурированным артефактам → использовать результат → проверить → принять ответственность.
3. Объяснять подход **spec-driven development** и вести его цикл на примере открытого инструмента [OpenSpec](https://github.com/Fission-AI/OpenSpec): предложение изменения → дельта спецификации → задачи → реализация агентом → проверка по спецификации → архивация.
4. Проводить границу ответственности: где AI бесполезен (неявные знания), что проверяет человек (human-in-the-loop), доменная валидация, правила безопасности.

Как проверить: артефакт портфеля - минимум один артефакт, созданный или проверенный с помощью AI, с описанием, что именно проверял человек; проведен цикл spec-driven development на кейсе - от change proposal до реализации, проверенной по критериям спецификации.

Границы и ответственность | где AI бесполезен (неявные знания), human-in-the-loop: что проверяет человек; доменная валидация результатов; правила безопасности (конфиденциальные данные, черновики AI не публикуются как есть); правовые рамки работы с AI в РФ - перед практикой обязательно прочитайте [Правовую справку](../materialy/pravovaya-spravka-rf.md) | 45 мин |

## Практика и артефакты портфеля

- Из неструктурированного текста с помощью AI: BPMN-модель, сущности, user stories - с последующей проверкой человеком.
- Автоматическая генерация описания процесса и списка требований из BPMN-модели.
- Change proposal по циклу spec-driven development для одного изменения в вашем кейсе: предложение, дельта спецификации, задачи и проверка реализации агента по критериям спецификации.
