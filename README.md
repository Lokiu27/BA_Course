# Репозиторий контента курса

Здесь находится только Markdown-контент курса «Бизнес-анализ и управление требованиями» и изображения. Вся инфраструктура (конфигурация MkDocs, сборка, деплой) — в основном репозитории **bolotova.online**.

Концепция курса: новый мир уже наступил — заказчики приносят идеи, аналитик превращает их в систему знаний, разработчик совместно с AI пишет код и поддерживает систему. AI используется в практике с первого модуля, а не как отдельная тема в конце. Стержень курса — цикл «намерение → спецификация → реализация → проверка → опыт» и подход spec-driven development: модуль 1 — намерение, модули 2–4 — спецификация (система знаний как код, модели, требования), модуль 5 — реализация и проверка (полный цикл SDD на OpenSpec), модуль 6 — опыт и роль аналитика. Каждый модуль держит структуру «теория → как это делали раньше → как теперь можно делать с AI».

## Структура репозитория

    course-content/
    ├── README.md                  — этот файл: инструкции для авторов
    ├── index.md                   — стартовая страница курса
    ├── itogovyy-proekt.md         — описание итогового проекта (портфель)
    ├── materialy/                 — скачиваемые шаблоны и рабочие материалы,
    │                               включая правовую справку (152-ФЗ, 98-ФЗ,
    │                               243-ФЗ об ИИ, правила работы с внешними AI)
    ├── modul-1/                   — модули курса
    │   ├── index.md               — обзор модуля: результаты, уроки, контрольная точка
    │   └── tema-N-....md          — уроки модуля
    ├── modul-2/ … modul-6/
    └── assets/images/             — изображения (PNG, JPG, SVG)

## Правила

- Имена файлов и папок: только строчные латинские буквы, цифры и дефисы.
- Главная страница каждого раздела называется `index.md`.
- Изображения размещаются в `assets/images/`, ссылки на них — относительные.
- Не добавлять конфигурацию MkDocs, Docker, nginx, CI/CD. Существующий `trigger-build.yml` в основном репозитории не изменять.
- Использовать стандартный Markdown: заголовки, списки, таблицы, блоки кода, ссылки. Не использовать расширения и HTML, поддержка которых не подтверждена.
- Формат исходников: один абзац — одна строка, один пункт списка — одна строка, одна цитата — одна строка. Не разбивать текст на строки вручную посередине предложения — при отображении строки переносятся сами. Переводы строк внутри текста допустимы только в блоках кода и ASCII-схемах.
- Внешние источники (IIBA и др.): указывать название материала, дату публикации и ссылку; цитаты на английском сопровождать переводом с пометкой «перевод»; перед публикацией проверять, что ссылки живы. Не цитировать закрытые (member-only) материалы без доступа к полному тексту.
- Правовые материалы (`pravovaya-spravka-rf.md`): обязательно датируйте («актуально на …») и проверяйте при каждом обновлении курса — реквизиты и нормы законов меняются. Ссылки на новости и кейсы дополняйте датой публикации.

## Методический стандарт урока

Курс асинхронный, без видео, в индивидуальном темпе. Каждый урок строится так (не механически — включайте только нужные элементы):

1. **«Что вы сможете делать после урока»** — результат через наблюдаемое действие и связь с рабочей ситуацией (сначала «зачем», затем «как»).
2. Ориентировочное время выполнения.
3. Опора на опыт учащегося, где она уместна.
4. Объяснение через контекст, примеры и контрпримеры.
5. Практика на кейсе курса или рабочих материалах учащегося — с критериями самопроверки.
6. Самопроверка (короткие вопросы с ответами).
7. Резюме и практический вывод.

## Технические требования к bolotova.online

Функции, которые нельзя реализовать только контентом. Требуют настройки основного репозитория или платформы:

1. **Навигация.** `nav` сайта автогенерируется скриптом `docs/generate_nav.py` основного репозитория по содержимому `course-content/`. При переименовании модулей и страниц — обновить подписи в `NAV_TITLES` этого скрипта.
2. **Рендеринг диаграмм.** В курсе используются блоки кода Mermaid, PlantUML и BPMN XML (в первую очередь в модуле 3). Требуется проверить, что платформа рендерит их (например, через `pymdownx.superfences` с custom fences), либо публиковать диаграммы как изображения в `assets/images/`.
3. **Скачивание материалов.** Сейчас шаблоны из `materialy/` открываются как обычные страницы. Если нужен именно файл для скачивания — потребуется настроить раздачу файлов платформой.
4. **Прогресс прохождения и напоминания.** Если нужны для курса — отдельная доработка платформы. В контенте не предполагаются.
5. **Канал вопросов.** Сейчас — e-mail на стартовой странице. Появление форума/чата — доработка платформы.
