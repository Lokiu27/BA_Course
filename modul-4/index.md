# Модуль 4. Артефакты как код (Doc-as-Code)

**Время модуля: 4–5 часов.** Статус: план модуля, уроки разрабатываются после
согласования структуры курса.

## Зачем этот модуль

Чтобы AI реализовывал и поддерживал систему знаний, артефакты должны быть
написаны на языке, который понимают и люди, и машины. Документы в бинарных
форматах и «зашумлённая» разметка для этого не годятся. Практика
**doc-as-code** — хранить артефакты аналитики как текст в системе контроля
версий — делает систему знаний машиночитаемой: AI может её читать,
анализировать и пополнять, а люди — версионировать, сравнивать и проверять.

Ключевая формула модуля:

```
diagram as code = AI-readable knowledge
```

## Результаты модуля

После модуля вы сможете:

1. Объяснять принцип requirements-as-code и его преимущества перед
   документами в бинарных форматах — прежде всего для совместной работы
   людей и AI.
2. Вести аналитику в Markdown и организовывать структуру репозитория
   документации.
3. Создавать диаграммы как код: Mermaid, PlantUML; хранить BPMN как XML.
4. Пользоваться базовыми операциями Git: коммит, история, ветки.
5. Настраивать автоматические проверки требований (линтинг): длина
   формулировок, запрещённые обороты, структура — правила, по которым
   «документация = машиночитаемая база знаний».

*Критерий достижения:* артефакт портфеля — doc-as-code репозиторий
аналитики: каталог с глоссарием, требованиями и моделью домена из модулей
2–3, минимум одна диаграмма в Mermaid или PlantUML, история коммитов.

## Уроки (план)

| Урок | О чём | Время |
|---|---|---|
| 4.1. Принцип requirements-as-code | почему «документ = репозиторий»; чем Markdown лучше бинарных форматов: минимум «шума» разметки для человека и LLM | 45 мин |
| 4.2. Markdown и структура репозитория аналитики | справочная разметка, каталог docs/: требования, домен, процессы, диаграммы | 60 мин |
| 4.3. Диаграммы как код | Mermaid и PlantUML (sequence, use case), BPMN XML как машиночитаемая модель процесса | 75 мин |
| 4.4. Git для аналитика и линтинг требований | репозиторий, коммит, история, ветки; автоматические проверки формулировок | 75 мин |

## Практика и артефакты портфеля

- Создание структуры репозитория аналитики и перенос в неё глоссария
  и моделей из модулей 2–3.
- Sequence-диаграмма в PlantUML или Mermaid (например, оформление заказа:
  Customer → Order → Payment).
- Первые автоматические проверки формулировок требований.

Итог модуля — центральный артефакт всего курса: ваш **репозиторий
аналитики** — та самая система знаний, которую в [модулях 5–6](../modul-5/index.md)
будут менять, трассировать и поддерживать с помощью AI.

## Что понадобится

- Редактор с поддержкой Markdown (например, VS Code) и предпросмотром
  Mermaid.
- Git (интерфейс командной строки или графический клиент).
